# TextPilot 详细规格说明书（v1.0）

> [!NOTE]
> 本文档为项目立项时的**初始开发规范（v1.0）**，仅作为最初设计的历史背景参考。具体实现的最新行为（如 Windows UI Automation 选区、`Ctrl+DoubleF8` 优化手势、`Ctrl+DoubleF9` 翻译手势、WebView2 界面及原生 Win32 接口实现）请以代码、测试及主 [README.md](../README.md) 为准。文档尾部第 14 节提供了从初始设计到当前版本（v0.5.0）的实际功能演进对照。

## 1. 项目概述
**项目名称**：TextPilot
**类型**：Windows 绿色单文件工具
**定位**：通过全局热键，将用户选中的文本（或剪贴板内容）发送给大模型 API，返回优化后的提示词，并自动写回剪贴板。
**核心价值**：让用户在任何软件中，选中一段提示词后按一个快捷键，即可获得更好的提示词，过程几乎无感知。
**设计原则**（必须严格遵守）：
- 极简：只做提示词优化这一件事
- 轻量：单文件 exe + 一个极小配置文件
- 绿色：免安装、可直接拷贝使用
- 低资源：常驻内存目标 ≤ 20MB，体积目标 ≤ 8MB
- 无干扰：默认无主窗口，仅系统托盘
---
## 2. 目标与非目标
### 2.1 目标（Must Have）
1. 单 exe 文件 + 同目录 `config.json`
2. 全局热键触发
3. 自动获取当前选中文本（优先）或剪贴板文本
4. 调用 OpenAI 兼容 API 进行提示词优化
5. 结果默认直接覆盖剪贴板
6. 系统托盘图标 + 右键菜单（设置、退出）
7. 配置文件自动创建与读写
8. 开机自启（可选）
9. 中文界面与提示
### 2.2 非目标（明确不做）
- 不支持本地大模型
- 不做历史记录、对话管理
- 不做复杂 GUI 主窗口
- 不做多语言切换（仅中文；此为初始 v1.0 历史约束，当前设置界面和站点的语言支持以主 README 为准）
- 不做自动更新
- 不做插件系统
- 不做流式输出（可后期考虑）
- 不做账号系统、云同步
---
## 3. 技术栈
| 模块 | 技术方案 | 备注 |
|------|----------|------|
| 语言 | Rust (Edition 2021) | - |
| Windows API | `windows` crate | 官方推荐 |
| 系统托盘 | `tray-icon` | 目前最稳定轻量 |
| 全局热键 | 自行封装 `RegisterHotKey` 或使用 `global-hotkey` | 优先自行封装以减少依赖 |
| HTTP 客户端 | `ureq` | 同步、体积小、无 async 运行时 |
| JSON | `serde` + `serde_json` | - |
| 剪贴板 | `clipboard-win` 或纯 Win32 | - |
| 配置路径 | exe 同目录 | 绿色便携 |
| 构建优化 | `opt-level = "z"` + LTO + strip | 体积优先 |
**禁止引入**：tokio、async-std、reqwest（默认 features）、egui/iced（除非后期明确需要弹窗）、任何大型 GUI 框架。

## 4. 程序架构
```
单进程 + 单消息循环
├── 启动
│ ├── 检查并加载/创建 config.json
│ ├── 注册全局热键
│ ├── 创建系统托盘图标
│ └── 进入消息循环
├── 热键触发
│ ├── 获取选中文本（模拟 Ctrl+C）
│ ├── 调用 API
│ └── 写回剪贴板 + 可选通知
├── 托盘菜单
│ ├── 打开设置（简单弹窗或直接打开 config.json）
│ ├── 重新加载配置
│ └── 退出
└── 退出时清理（注销热键等）
```
全程同步执行，无额外线程（除托盘库可能自带的极轻量线程）。

## 5. 功能详细规格
### 5.1 全局热键
- 默认热键：`Ctrl + Shift + O`
- 支持用户在配置文件中修改（格式示例：`Ctrl+Shift+O`、`Alt+Q` 等）
- 启动时注册，退出时注销
- 若热键被占用，托盘提示“热键注册失败，请修改配置后重新加载”
### 5.2 文本获取逻辑（优先级）
1. 尝试获取当前选中文本：
   - 备份当前剪贴板
   - 模拟发送 `Ctrl + C`
   - 等待 80–120ms
   - 读取剪贴板
   - 若成功且内容非空，使用该内容
2. 若选中文本获取失败或为空，则直接使用当前剪贴板内容
3. 若两者都为空，则托盘提示“未检测到文本”并中止
### 5.3 API 调用
- 仅支持 OpenAI 兼容接口（`/v1/chat/completions`）
- 请求方法：POST
- 超时：25 秒
- 请求体最小字段：
  ```json
  {
    "model": "从配置读取",
    "messages": [
      {"role": "system", "content": "从配置读取的系统提示词"},
      {"role": "user", "content": "用户文本"}
    ],
    "temperature": 从配置读取,
    "max_tokens": 2048
  }
  ```
- 成功后只取 `choices[0].message.content`，去除首尾空白
- 失败时托盘通知具体错误（网络、401、超时等）
### 5.4 结果处理
- **默认模式**（`result_mode = "clipboard"`）：
  - 直接覆盖剪贴板
  - 可选播放系统默认提示音（可配置开关）
  - 托盘短暂提示“已优化并复制到剪贴板”
- 预留 `result_mode = "popup"`（后期实现极简弹窗）
### 5.5 系统托盘
- 图标：使用内嵌的简单图标（程序自带）
- 鼠标左键单击：无动作（或显示状态）
- 右键菜单：
  1. 设置（打开配置文件或简单设置窗口）
  2. 重新加载配置
  3. 退出
- 鼠标悬停提示：显示当前状态（如“运行中 | 热键: Ctrl+Shift+O”）
### 5.6 配置管理
- 文件位置：与 exe 同目录的 `config.json`
- 启动时行为：
  - 存在 → 加载
  - 不存在 → 自动创建默认配置，并提示用户填写 API Key
- 支持手动编辑后点击“重新加载配置”生效（热键变更需要重新注册）

## 6. 配置文件规格（config.json）
```json
{
  "api_key": "",
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-4o-mini",
  "hotkey": "Ctrl+Shift+O",
  "temperature": 0.3,
  "max_tokens": 2048,
  "system_prompt": "你是一个专业的提示词优化专家。请将用户提供的原始提示词改写得更加清晰、具体、结构良好且有效。只返回优化后的提示词内容，不要添加任何解释、前缀或后缀。",
  "result_mode": "clipboard",
  "play_sound": true,
  "auto_start": false
}
```
**字段说明**：
- `api_key`：必填，用户自行填写
- `base_url`：支持任何 OpenAI 兼容服务（DeepSeek、通义、Groq、本地代理等）
- `hotkey`：字符串，程序解析为修饰键 + 主键
- `system_prompt`：允许用户完全自定义
- `result_mode`：目前仅实现 `clipboard`
- `auto_start`：是否写入注册表实现开机启动

## 7. 用户操作流程
### 首次使用
1. 解压/拷贝 `TextPilot.exe`
2. 双击运行 → 自动生成 `config.json`
3. 托盘图标出现 → 右键「设置」→ 填写 API Key 并保存
4. 开始使用
### 日常使用
1. 在任意软件中选中一段提示词
2. 按下 `Ctrl + Shift + O`
3. 等待 0.5–3 秒
4. 直接 `Ctrl + V` 粘贴优化后的结果
### 修改配置
- 右键托盘 → 设置 → 编辑 config.json → 保存 → 重新加载配置

## 8. 性能与资源目标
| 指标 | 目标值 |
|------|--------|
| 发布体积（release） | ≤ 8 MB（争取 5 MB 以内） |
| 常驻内存 | ≤ 20 MB（理想 12–16 MB） |
| 启动到托盘可见 | < 300ms |
| 热键响应到开始请求 | < 150ms |
| 无网络时的失败反馈 | < 1s |
构建必须开启：
```toml
[profile.release]
opt-level = "z"
lto = true
codegen-units = 1
panic = "abort"
strip = true
```
---
## 9. 错误处理与用户反馈
| 场景 | 处理方式 |
|------|----------|
| 热键注册失败 | 托盘通知 + 提示修改配置 |
| 未检测到文本 | 托盘短暂提示 |
| API Key 为空 | 提示去设置填写 |
| 网络错误 / 超时 | 托盘显示具体错误信息 |
| API 返回非 200 | 显示状态码与错误信息 |
| 配置文件损坏 | 备份原文件并重新生成默认配置 |
所有反馈优先使用托盘通知（Balloon Tip），避免弹出打扰性窗口。

## 10. 安全与隐私
- API Key 仅存储在本地 `config.json`，不做任何上传
- 请求只发送用户选中的文本，无其他数据采集
- 不写运行日志（除非错误时写极简错误日志到同目录）
- 程序退出后无残留进程

## 14. 实际功能演进对照（v0.5.0 补充说明）

随着项目迭代至 **v0.5.0** 版，程序实际完成的功能已大大超越初始规格说明书的设计范围。现记录主要特性差异表如下：

| 模块 | 初始规范 (v1.0 设计) | 当前实现 (v0.5.0 实际状态) |
|---|---|---|
| **核心交互与热键** | 仅支持单一热键（如 `Ctrl+Shift+O`）触发提示词优化 | 支持 **优化热键 (`Ctrl+DoubleF8`)** 与 **翻译热键 (`Ctrl+DoubleF9`)** 两套独立触发键；内置按键及多击手势防冲突校验 |
| **功能范围** | 仅做提示词优化 | 新增 **智能文本翻译** 功能，基于 AI 大模型识别主语种，实现“母语”与“目标语言”间的自动双向翻译 |
| **模型配置** | 单一 API Key / 单一 Model | 引入命名多套 API Profile；每个动作可独立绑定指定 Profile 与其中的具体模型，运行时按动作绑定 Profile 检查 API Key，不受设置页当前打开但未被使用的 Profile 影响 |
| **图形设置页面** | 无界面 / 纯手动修改 JSON | 内置 WebView2 渲染的 Apple / Win11 风格设置界面，支持一键连通性测试、输入表单自动暂存与数据全面严格校验 |
| **选区读取逻辑** | 模拟 Ctrl+C / 使用剪贴板代理 | 优先使用 Windows UI Automation 直接读取控件文字；失败时自动临时使用剪贴板兼容模式并安全恢复原数据 |
